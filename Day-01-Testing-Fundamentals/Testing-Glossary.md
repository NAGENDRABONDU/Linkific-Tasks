# Testing Glossary

Common terms used in software testing and their simple meanings.

| Term | Simple Definition |
|---|---|
| **Software Testing** | Checking software to find defects and verify that it works as expected. |
| **QA** | Preventing defects by improving the development process. |
| **Verification** | Checking whether the product is being built correctly. |
| **Validation** | Checking whether the right product is being built. |
| **Error** | A human mistake. |
| **Defect** | A problem in the software. |
| **Failure** | Incorrect software behavior during execution. |
| **Test Scenario** | What needs to be tested. |
| **Test Case** | Detailed steps used to test something. |
| **Expected Result** | What should happen. |
| **Actual Result** | What actually happens. |
| **Test Data** | Data used for testing. |
| **Test Suite** | A collection of test cases. |
| **Severity** | The impact of a defect on the software. |
| **Priority** | How urgently a defect should be fixed. |
| **Regression Testing** | Checking existing functionality after a change. |
| **Re-testing** | Testing a specific defect again after it is fixed. |
| **Smoke Testing** | A quick check of critical features of a new build. |
| **Sanity Testing** | A focused check of changed or affected functionality. |
| **Test Environment** | The setup used to test the software. |
| **Test Execution** | Running test cases and recording the results. |
| **Build** | A version of the software provided for testing. |
| **Requirement** | A feature or condition that the software must satisfy. |
| **Bug** | A defect or problem found in the software. |
