# Bug Report Template

- **Bug ID:** [Tracker-generated ID]
- **Summary:** [Area/action + observed failure]
- **Description / Impact:** [Context and who/what is affected]
- **Preconditions:** [Account state, setup, feature flags, data]
- **Steps to Reproduce:**
  1. [First action]
  2. [Second action]
  3. [Action that exposes the issue]
- **Expected Result:** [Behavior required]
- **Actual Result:** [Observed behavior; exact error text if useful]
- **Severity:** [Critical / Major / Minor / Trivial, per project definitions]
- **Priority Recommendation:** [P1 / P2 / P3 or project scale]
- **Priority Rationale:** [Business urgency and impact]
- **Environment:** [App/build, OS, browser/device, version]
- **Test Data:** [Non-sensitive identifier or masked data]
- **Attachments:** [Screenshot/video/log/request-response; redact secrets]
- **Frequency:** [Always / Intermittent / Once, only if observed]
- **Reporter:** [Name/team]
- **Date Reported:** [YYYY-MM-DD]
- **Status:** [New / project workflow status]
- **Related Issues:** [Related IDs if applicable]

## Quality checklist
- [ ] Summary is specific.
- [ ] Steps are numbered and reproducible.
- [ ] Expected and actual results are distinct.
- [ ] Environment/build is recorded.
- [ ] Severity/priority follow team definitions.
- [ ] Evidence contains no secrets.
- [ ] One issue is described using neutral language.
